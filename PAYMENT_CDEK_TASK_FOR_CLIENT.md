# Regola: данные для запуска оплаты T-Банка и доставки СДЭК

## Что уже реализовано

- сервер заново загружает товары и цены из БД и не доверяет сумме из браузера;
- T-Банк: создание платежа через `/v2/Init`, чек, защищённая подпись Token, переход на платёжную форму;
- webhook T-Банка: проверка подписи, суммы, номера заказа и PaymentId, идемпотентное обновление статуса;
- СДЭК API v2: OAuth, поиск города, расчёт тарифа, список ПВЗ, создание отправления из админки;
- оплата при получении СДЭК и отдельный безопасный сценарий для предоплаченного заказа;
- статусы платежа, номер/UUID СДЭК и управление отправлением в админ-панели;
- без ключей онлайн-оплата отключена, а сайт продолжает принимать заявки по счёту.

## Что предоставить для T-Банка

1. Заключить договор интернет-эквайринга T-Банка для домена `regola.shop`.
2. В личном кабинете получить отдельные тестовые и боевые `TerminalKey` и пароль терминала.
3. Подтвердить систему налогообложения: `osn`, `usn_income`, `usn_income_outcome`, `esn` или `patent`.
4. Подтвердить ставку НДС для товара и доставки в формате API T-Банка, например `none`, `vat0`, `vat10`, `vat20`.
5. Указать, кто формирует онлайн-чек: касса T-Банка/облачная касса/собственная ККТ. Если чек формирует банк, включить фискализацию терминала.
6. Подтвердить одностадийную оплату и разрешённые способы оплаты на форме банка.
7. Передать безопасным каналом:

```env
TBANK_MODE=test
TBANK_TERMINAL_KEY=
TBANK_PASSWORD=
TBANK_TAXATION=
TBANK_ITEM_TAX=
TBANK_DELIVERY_TAX=
```

В кабинете банка разрешить адрес уведомлений:

```text
https://regola.shop/api/payments/tbank/notification
```

Пароль терминала нельзя отправлять в чат заказов, хранить в GitHub или вставлять в админ-панель сайта.

## Что предоставить для СДЭК

1. Заключить договор СДЭК для юридического лица/ИП и получить доступ к API v2.
2. Отдельно согласовать наложенный платёж, лимиты и порядок перечисления собранных средств магазину.
3. Получить тестовые и боевые `Client ID` и `Client secret`.
4. Сообщить код города отправителя и код склада/ПВЗ отгрузки (`shipment_point`).
5. Подтвердить тарифы «до ПВЗ» и «курьером», которыми разрешено пользоваться по договору.
6. Передать средние параметры одного упакованного товара: вес в граммах и габариты в сантиметрах.
7. Передать имя/название и телефон отправителя.
8. Передать безопасным каналом:

```env
CDEK_MODE=test
CDEK_CLIENT_ID=
CDEK_CLIENT_SECRET=
CDEK_FROM_CITY_CODE=
CDEK_TARIFF_PVZ=
CDEK_TARIFF_COURIER=
CDEK_PACKAGE_WEIGHT_G=
CDEK_PACKAGE_LENGTH_CM=
CDEK_PACKAGE_WIDTH_CM=
CDEK_PACKAGE_HEIGHT_CM=
CDEK_SHIPMENT_POINT=
CDEK_SENDER_NAME=
CDEK_SENDER_PHONE=
```

## Решения, которые должен письменно подтвердить заказчик

- ИП/ООО, ИНН, ОГРН, юридическое название и расчётный счёт;
- схема налогообложения и НДС, согласованные с бухгалтером;
- кто оплачивает доставку и можно ли включать её в онлайн-платёж;
- допускается ли наложенный платёж и для каких городов/сумм;
- вес и габариты каждого типа упаковки;
- политика отмены заказа, возврата денег и возврата товара;
- телефон и email, которые показываются покупателю после оформления;
- ответственное лицо, которое принимает тестовые платежи и отправления.

## Порядок включения

1. Заполнить тестовые ключи на сервере и оставить режимы `test`.
2. Пройти тест-кейсы оплаты: успех, отказ, отмена, повторный webhook, неверная сумма, возврат.
3. Пройти тесты СДЭК: ПВЗ, курьер, предоплата, наложенный платёж, ошибка города/тарифа.
4. Проверить чеки с бухгалтером и тестовой кассой.
5. Получить письменное подтверждение заказчика.
6. Заменить ключи на боевые, поставить `TBANK_MODE=production` и `CDEK_MODE=production`, пересоздать контейнер.
7. Провести один минимальный реальный заказ и проверить зачисление, чек и отправление.

Официальная документация: [T-Банк — интернет-эквайринг](https://developer.tbank.ru/eacq/intro/developer/openapi), [СДЭК API](https://api-docs.cdek.ru/).
